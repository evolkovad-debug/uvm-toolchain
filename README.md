# Ассемблер и интерпретатор УВМ

## 1. Общее описание

Учебная виртуальная машина (УВМ): стековая машина с отдельной памятью
команд и памятью данных. Проект содержит ассемблер (JSON в машинный
код) и интерпретатор. Реализованы все этапы: ассемблер (JSON, внутреннее представление,
машинный код), интерпретатор с командами загрузки, чтения, записи и
сдвига вправо, дамп памяти в формате XML и тестовая задача над
векторами.

## 2. Язык ассемблера и настройки

Программа — JSON-список команд. Каждая команда — объект с полем `op`
и операндами:

| op           | Операнды                 | Что делает                      |
|--------------|--------------------------|---------------------------------|
| `load_const` | `value`                  | положить `value` на стек        |
| `read`       | `address`                | положить на стек память[address]|
| `write`      | `offset`                 | снять значение и адрес со стека |
| `shr`        | `address`, `offset`      | логический сдвиг вправо         |

Все операнды — целые числа от 0 до максимума, который помещается в
поле команды (`value` — 26 бит, `address` — 18 бит, `offset` у `write`
и `shr` — 15 бит). Лишние и пропущенные поля считаются ошибкой.

Пример:

    [
      {"op": "load_const", "value": 1009},
      {"op": "shr", "address": 208, "offset": 386}
    ]

Параметры ассемблера:

- `ИСХОДНИК` — путь к JSON-файлу с программой.
- `ВЫХОД` — путь к двоичному файлу-результату.
- `--test` — режим тестирования: вывести байты команд на экран.

При ошибке печатается «Ошибка: ...», код возврата 1.

Формат машинного кода: команда — целое число, собранное из полей
(поле A занимает биты 0–5, остальные поля — свои биты по спецификации),
записанное в байты по порядку от младшего к старшему. Размеры команд:
`load_const` — 4 байта, `read` и `write` — 3, `shr` — 5.
Результат записывается в двоичный файл без разделителей. После
ассемблирования выводится число команд.

## Интерпретатор

Память команд (байты программы) и память данных (262144 ячейки,
32-битные слова, сначала нули) разделены. Есть стек значений.

- `load_const` — кладёт `value` на стек;
- `read` — кладёт на стек значение ячейки `address`;
- `write` — снимает со стека значение, затем снимает адрес и записывает
  значение в ячейку «адрес + `offset`»;
- `shr` — побитовый логический сдвиг вправо: первый операнд — ячейка
  `address`, второй операнд (на сколько бит сдвигать) снимается со
  стека; затем со стека снимается адрес, и результат записывается в
  ячейку «адрес + `offset`». Исходная ячейка не меняется.

Цикл работы: прочитать команду из двоичного файла, перевести в поля
A, B, C, выполнить. Выход за память данных или пустой стек — ошибка.

Параметры интерпретатора:

- `ПРОГРАММА` — двоичный файл, полученный ассемблером.
- `ДАМП` — путь к XML-файлу с дампом памяти.
- `--range ПЕРВЫЙ:ПОСЛЕДНИЙ` — диапазон адресов для дампа
  (включительно).

Формат дампа: корневой элемент `memory`, внутри элементы `cell` с
атрибутом `address` и значением ячейки в тексте.

## 3. Запуск и тесты

    ./run.sh asm examples/spec_tests.json out.bin --test
    ./run.sh vm out.bin dump.xml --range 0:24
    python3 -m unittest discover -s tests -t .

## 4. Примеры

    ./run.sh asm examples/spec_tests.json out.bin --test

Вывод:

    Ассемблировано команд: 4
    0x40, 0xFC, 0x00, 0x00
    0x24, 0x35, 0x00
    0xE6, 0xA9, 0x00
    0x3D, 0x34, 0x00, 0x82, 0x01

Содержимое файла можно посмотреть командой `hexdump -C out.bin`.

Тестовая программа: копирование массива из пяти элементов
(ячейки 0–4) в ячейки 20–24.

    python3 examples/make_copy.py
    ./run.sh asm examples/copy_array.json out.bin
    ./run.sh vm out.bin dump.xml --range 0:24

Фрагмент дампа:

    <cell address="20">11</cell>
    <cell address="21">22</cell>
    <cell address="22">33</cell>
    <cell address="23">44</cell>
    <cell address="24">55</cell>

Проверка команды `shr` (результаты в ячейках 10, 11, 13, 14, 15):

    python3 examples/make_shr.py
    ./run.sh asm examples/shr_test.json out.bin
    ./run.sh vm out.bin dump.xml --range 0:15

Тестовая задача: поэлементный сдвиг вправо двух векторов длины 5.
Первый вектор лежит в ячейках 100–104, второй — в 110–114, результат
записывается в первый вектор. Три примера в `examples/vectors_*.json`:

    python3 examples/make_vectors.py
    ./run.sh asm examples/vectors_1.json out.bin
    ./run.sh vm out.bin dump.xml --range 100:114

| Пример | Первый вектор            | Второй вектор | Результат               |
|--------|--------------------------|---------------|-------------------------|
| 1      | 256, 1024, 7, 100, 65535 | 4, 3, 1, 2, 8 | 16, 128, 3, 25, 255     |
| 2      | 1, 2, 4, 8, 16           | 0, 1, 2, 3, 4 | 1, 1, 1, 1, 1           |
| 3      | 1000000, 500, 33, 1048576, 12345 | 10, 5, 0, 20, 3 | 976, 15, 33, 1, 1543 |
